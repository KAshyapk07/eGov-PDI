1 The Problem We Are Solving

DIGIT Health Campaign Management (HCM) is used by governments across Africa and South Asia to run public health campaigns — distributing bednets, delivering malaria medication, running vaccination drives, and more. These campaigns rely on field workers visiting households, registering people, and delivering interventions.

Today, the system has two fundamental blind spots that undermine every campaign:

Blind Spot 1: "We don't know how many people we're supposed to reach"

The Denominator Problem

Coverage is calculated as People Served / People Registered. But "Registered" is not the same as "Actually Exist." If a village has 1,200 people but only 800 were found and registered, the system shows 100% coverage (800/800) when reality is 67% (800/1,200). 400 people are invisible to the system.

Blind Spot 2: "We don't know when we've counted someone twice"

The Duplication Problem

Spelling variations ("Rahim" vs "Raheem"), different campaign rounds, different teams, and offline sync issues cause the same person to be registered multiple times. The system counts each as a separate beneficiary, inflating service numbers by 10-30%.

4 What We Are Building

Two independent capabilities that plug into the existing DIGIT HCM platform:

Capability 1: Population Denominator Intelligence (PDI)

Answers: "Who are we missing?"

Uses satellite population data and building footprints to estimate the true population of every campaign area, then compares against registrations to find gaps.

Feature

Population Estimation

Estimate expected population and households using WorldPop satellite data and Google Open Buildings. Provides a confidence score.

Feature

Coverage Gap Detection

Compare expected vs. registered. Classify each settlement as Green (on track), Yellow (moderate gap), or Red (critical gap).

Feature

Invisible Settlement Detection

Find places where buildings exist in satellite data but no households are registered. Alert supervisors to these communities.

Feature

Risk Scoring

Score settlements 0-100 based on population gap, past performance, facility distance, building density. Prioritize highest-need areas.

Feature

Web Dashboard

KPI summary cards, interactive color-coded map, gap charts, invisible settlement table, and risk-ranked list for campaign managers.

Feature

Mobile Summary Cards

Supervisors see expected vs. registered for each area on their phone. Coverage percentage and risk level. Works offline.

Capability 2: Beneficiary Deduplication Engine (BDE)

Answers: "Have we already registered this person?"

Instantly checks for duplicate registrations on the device itself, even without internet. Shows matches to field workers for confirmation.

Feature

Fuzzy Name Matching

"Rahim" and "Raheem" are detected as possible matches. Handles spelling variations and name reordering.

Feature

Multi-Attribute Scoring

Checks name, age, gender, guardian, village, household, and GPS. Produces a confidence score (e.g., "89% likely duplicate").

Feature

Offline-First Design

Runs entirely on the phone. No internet required. Uses the existing local database. Critical for low-connectivity campaign areas.

Feature

Reusable Flutter Package

Built as a standalone package any DIGIT app can add. Works for bednet distribution, vaccination, malaria prevention, and future campaigns.

Feature

Server-Side Cross-Check

When data syncs to the server, a second check catches duplicates across different teams and villages.

Feature

Supervisor Review Queue

Suspected duplicates go to a review queue. Supervisors confirm or reject. Confirmed duplicates are merged.

5 How It Works — High-Level Design

This section explains the system without technical jargon. Think of it as "the story of how data flows."

5.1 Population Intelligence — Four Steps

1
Gather Data
Download satellite population grids (WorldPop) and building footprints (Google Open Buildings) for campaign area
2
Compute Estimates
For each settlement: sum population grid = estimated people. Count buildings = estimated households.
3
Find Gaps
Compare estimated vs. registered. Expected 1,200 but registered 680 = 520 people missing (43% gap).
4
Visualize
Color-coded map (Green/Yellow/Red), invisible settlement alerts, risk-ranked lists, dashboard cards.
How do we estimate population from satellites?

WorldPop provides calibrated population grids — a 100-meter grid where each cell estimates how many people live there (calibrated against census data). We sum cell values within each boundary.

Google Open Buildings used AI to detect 1.8 billion building footprints from satellite imagery across Africa, South Asia, and Latin America. We count buildings in each area. If average household size is 5, then 240 buildings = ~1,200 people.

We combine both methods. When they agree, confidence is high. When they diverge, we flag for review.

How does "fuzzy" name matching work?
  • Sound-alike matching: Encodes names by how they sound. "Rahim" and "Raheem" produce the same sound code.
  • Character similarity: Measures closeness character-by-character. "Rahim" and "Raheem" share most characters.
  • Name reordering: "Mohammed Ali" and "Ali Mohammed" recognized as potentially the same person.

Then 7 attributes (name, age, gender, guardian, village, household, GPS) combine into a single confidence score.

Key Assumptions

  • WorldPop and Google Open Buildings data covers target campaign countries (confirmed for most of Africa, South Asia)
  • Household registrations include GPS coordinates (confirmed)
  • Average household size available per region (from census/configuration)
  • Campaign boundaries are defined as polygons in HCM
  • Target devices have 2GB+ RAM and 1GB+ free storage
  • Field workers can judge whether flagged duplicates are the same person
